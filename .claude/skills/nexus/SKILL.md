# Nexus Question/Topic Engagement

Runs a single question or topic through The Nexus's full agent chain per `Nexus Workflow.md` — the source of truth for this process; re-read it before running in case it has changed since this skill was written. (It has changed at least once already — this skill previously described a stale six-agent, Sherlock-first sequence; don't assume this file is current without checking.)

## Before running

Confirm GitHub access: `gh auth status`. Stop and ask Rick to run `gh auth login` himself if not authenticated (interactive — cannot be scripted). The deliverable is a commit directly to `main`; don't proceed without confirmed access.

If the question is actually the recurring CIR-driven cyber-intelligence pull from `Sources.md`, use the `nexus-daily-report` skill instead — this skill is for one-off engagements on a specific question or topic.

Artifact-library candidates surface **during** the run, not as a separate afterthought: Sherlock, Ryan, Euclid, Popper, Seldon, and Tufte each flag sources worth keeping as they hand the draft along (see Execution sequence below), and Alexandria evaluates all of it at the very end and brings her own recommendation to Rick, who makes the final call. **Do not submit a Pull Request against `nexus-artifacts` mid-run or without Rick's go-ahead** — Alexandria's closing recommendation goes into the published report; only invoke the `nexus-artifact-submit` skill afterward if Rick says to proceed. Separately, check for pending artifact approvals and mention them to Rick as a footer: `gh pr list --repo raceBannon99/nexus-artifacts --state open` (see `Nexus Artifact Repository.md`).

If the request is a **revision to a report already published** (not a new question/topic) — e.g. "add sources to X," "fix the multisig figure in the Harmony report," "incorporate this new source" — this is an **Update Pass**, not a full engagement. Skip to that section below instead of running the full sequence — and skip stage 0 (Bradlee's pre-flight check) as well; the question was already scoped in the original run.

## Execution sequence

Eleven stages, not six — a pre-flight check (Bradlee, stage 0) ahead of the ten-stage chain, in which Alexandria opens and closes (appearing twice) and Bradlee also closes (his third appearance overall, counting the pre-flight). Each stage analyzes the question through its own guiding question, gathers what it needs, hands off to the next, and (from Sherlock through Tufte) flags any source worth keeping permanently in the artifacts library:

0. **Bradlee (pre-flight)** — *Any clarifying questions?* Reads only Rick's raw question — nothing else exists yet. Judges whether it's genuinely ambiguous in a way that would change the shape of the answer (scope, timeframe, key-term definitions, what's in or out of bounds) — not pedantic or low-stakes ambiguity. **If so, asks Rick a small number of clarifying questions** (the `AskUserQuestion` tool fits well here — recommended option first, free-text via "Other" when a fixed choice doesn't capture it) **before anyone else does any work**, on the reasoning that it's wasted effort to have Alexandria research a question that might still get rescoped. If Rick leaves a question unanswered or says to use judgment, Bradlee proceeds with a **stated, logged assumption** rather than blocking the run. If the question is already well-scoped, he says so plainly and passes it on immediately — most runs should show none asked, the same "say so plainly" pattern Turing uses for New Skills. Either outcome is recorded in a mandatory **"Clarifying Questions" section** (placed just under Bradlee's closing-synthesis section at the top of the report, ahead of Alexandria's "What do we already know?" section — see step 8 below for why the synthesis itself stays first). Not run during Update Passes — the original question was already scoped in the report's first pass. Passes the (possibly scoped) question to Alexandria.
1. **Alexandria (opening)** — *What do we already know?* Check the artifact library (`raceBannon99/nexus-artifacts`) for anything that might answer the question — she may find nothing, and should say so plainly rather than force a connection. Also worth checking `raceBannon99/The-Nexus` for prior relevant reports/precedent, even though that's a separate repo from the Library — for a content-level check (grepping report *text* for keywords, not just listing filenames via `gh api`), use `.claude/scripts/nexus-search-reports.sh <clone-parent-dir> <term> [term ...]` (already allowlisted as a single fixed command; clones fresh and greps `reports/`). **Do not hand-write this as a `CLONE_DIR="..." ; git clone ...; grep ...` sequence** — that compound/variable-wrapped form won't match the allowlist and will prompt for permission every run. Creates the **Sources section** in the draft right here, at the start — it isn't assembled at the end anymore, it accumulates as every later stage adds to it. Passes the draft to Sherlock.
2. **Sherlock** — *What are the facts?* Research the question/topic directly, adding sources to the Sources section as he goes. **Standing rule: if a WebFetch call fails for any reason (blocked, timeout, error), retry via Chrome MCP (`navigate` then `get_page_text`) before treating the source as unreachable.** Confirmed working 2026-07-17 against a site (arstechnica.com) that blocks WebFetch/WebSearch entirely — Chrome MCP retrieved full content cleanly. Cite the real source URL as the hotlink/citation regardless of which tool read the content. **Substack thesis-tracking (added 2026-09-21, per Rick's direct instruction).** Check `Intelligence Reports/First Principles Newsletter Tracker.md` for any standing thesis (Rick's own Substack conclusions, drawn from Nexus's own intelligence work — "the primary reason we build the Nexus system," per Rick) that this question bears on. Where one exists, add the essay itself to the Sources section as a real source, not a passing mention, and reason explicitly whether today's evidence supports, complicates, or contradicts it — appending a dated Evidence Log entry to that file regardless of outcome (see its own Rules for the Supports/Complicates/Contradicts/Ambiguous discipline; this is belief-tracking, not a duplicate-check). Flags anything worth archiving, then passes to Ryan.
3. **Ryan** — *What does the adversary playbook look like here?* (Added 2026-08-17.) Reviews the draft for anything adversary- or campaign-related — a named threat actor, a specific attack campaign, active Adversary Playbook activity per the CIR taxonomy. If the engagement involves a specific attack campaign, characterizes it using the Lockheed Martin Kill Chain paper, the Diamond Model, and MITRE ATT&CK, and applies the standing Cyber Kill Chain report convention (Timeline section, Evidence Tier framework — see `Nexus Workflow.md`'s "Standing Conventions for Specific Report Types") where the report type calls for it. Tags attribution carefully, distinguishing suspected nation-state, vendor-assigned group name, campaign name, and malware name from one another — this feeds Popper's later campaign-vs-actor-attribution stress test rather than replacing it. If the campaign is new or has updated status, flags what needs to change in `Intelligence Reports/Adversary Tracking Report.md` — Tufte handles the actual formatting of that update at his stage below (joint ownership added 2026-08-17: Ryan decides what belongs in the table, Tufte decides how it's presented). If Sherlock cited a First Principles Newsletter Tracker essay bearing on adversary/campaign characterization (e.g. the "How Many Active Adversary Campaigns?" thread), factors Rick's own prior position into his own tagging rather than re-deriving it from scratch. If the question doesn't involve a specific adversary or campaign, says so plainly and passes the draft on unchanged rather than forcing an adversary angle onto every engagement. Flags library candidates, passes to Euclid.
4. **Euclid** — *What must be fundamentally true?* Reads the Sources section and writes the first draft answer, reasoning from first principles — independent of vendor claims or conventional wisdom. If a First Principles Newsletter Tracker essay is among the sources, reasons from it as a genuine input — Rick's own prior first-principles conclusion on this exact ground — testing it against today's evidence the same way he tests any other source, not treating it as background color. Flags library candidates, passes to Popper.
5. **Popper** — *How could we be wrong?* Genuine pushback against Euclid's analysis (and Sherlock's, Ryan's, or Alexandria's, if warranted) — devil's advocate, not softened agreement. Where Euclid's draft leans on a First Principles Newsletter Tracker thesis, stress-tests that thesis itself with the same rigor — this is exactly the "is it time to change my mind" check the tracker exists to prompt, not a courtesy exemption for Rick's own prior published view. Flags library candidates, passes to Seldon.
6. **Seldon** — *What is likely to happen next?* Reads Euclid's answer and Popper's objections together, reasons from probabilistic thinking and uncertainty, and updates the draft. This is where Popper's challenges get resolved, not just noted — address each one explicitly (revised, or stood by with reasoning) rather than leaving a critique dangling; then add forward-looking forecasts. **Every forecast is a range with a median, never a single point probability or confidence percentage** (see `Agent Seldon Concept.md`, updated 2026-07-22) — say it in plain language ("the range runs from about X to Y, with a median around Z"), not statistical notation like "P5/P95." **Every range, on every citation, also carries the uncertainty-window/years-to-median narrative** (added 2026-09-27, per Rick's instruction — see the `nexus-forecast-narrative` skill for the exact formula and this ad-hoc engagement's own plain-language phrasing). Reframe binary "will X happen" questions as a range-bearing quantity instead, most often years-until-event, or a share/degree estimate when timing isn't the real uncertainty. State what drives each end of the spread, and flag plainly when a range is reasoned judgment rather than measured data. If a cited First Principles Newsletter Tracker essay carries an implicit probabilistic claim or dated prediction (e.g. "Disrupting the Disruptor"'s six-year SASE-disruption forecast), weighs and updates it with the same discipline applied to the standing Singularity/AGI/Superintelligence forecast files. Flags library candidates, passes to Tufte.
7. **Tufte** — *How do we make this clear?* Scans the draft for places a visualization would help. When it's the clearest way to show the tension, visualizes a First Principles Newsletter Tracker thesis against current evidence (a prior-position-vs-new-evidence diagram) — a "when appropriate" tool, not mandatory on every engagement that cites the tracker. **Two lanes, not one (standing convention, 2026-08-04):** genuine tabular data (a Timeline, a simple side-by-side fact comparison) gets a markdown table — that's the right tool for it. A true diagram — a flowchart, a process or comparison diagram, anything where spatial layout or visual flow carries the information, not just the values — gets built as an **actual rendered image file**, not approximated as a text table. Test: would spatial position or flow carry information a table's rows and columns can't? If yes, it's a diagram. **Mechanism for a real diagram (updated 2026-08-27): invoke the `epic-infographics` skill — mandatory for every Tufte diagram/infographic, not a first choice among options.** It replaces the earlier `dataviz`-plus-hand-rolled-headless-Chrome-CLI pipeline: `epic-infographics` picks the design language itself, builds the self-contained HTML/inline-SVG file, runs a mechanical preflight (`scripts/check.mjs`) that catches text collisions, clipped text, and canvas-escape errors before rendering, then renders the PNG via its own bundled Playwright script (`scripts/render.mjs`) — no separate headless Chrome invocation or local HTTP server needed. Tufte still does the mandatory step the old convention required: look at the rendered PNG and fix anything wrong before calling it done. (One-time-per-machine setup — `npm install && npx playwright install chromium`, run from the skill's own package directory — isn't a per-diagram step.) **Every rendered diagram carries the First Principles Consulting mark (standing convention, 2026-08-28):** bottom-right or bottom-left, whichever corner is free of a title block/legend/key — never stacked on or width-matched to one. Pick whichever pre-made transparent variant reads against that diagram's background at that corner — `assets/first-principles-consulting-logo-white.png` (light ink) for dark backgrounds, `assets/first-principles-consulting-logo-black.png` (dark ink) for light ones — sized small, like a mark in the corner of a slide, not a panel. See `Agent Tufte Concept.md`'s 2026-08-28 entry for the full mechanism and why the raw logo file (`assets/first-principles-consulting-logo.png`, opaque white background, no alpha) can't be dropped in directly.

Save the rendered file into the repo (`reports/images/YYYY-MM-DD-topic-slug/` for a one-off graphic, `assets/` for something reusable), and embed it with `<img src="https://raw.githubusercontent.com/raceBannon99/The-Nexus/main/<path>">` — the same by-URL pattern already used for the First Principles Consulting logo, not a base64 embed. Not every report needs a diagram; don't force one where prose or a table already does the job. (The Adversary Tracking Report's per-category table images and heatmap below also go through `epic-infographics` now, as of 2026-08-27 — `build_tables.py` generates the HTML, styled with the editorial design language's tokens, and `check.mjs`/`render.mjs --preset tall --width 1580` replace the old Pillow autocrop pipeline; see `Agent Tufte Concept.md`'s same-day follow-up entry for the exact workflow.) **If Ryan flagged an Adversary Tracking Report update at his stage above, format it here too** (added 2026-08-17) — real structural authority (column set, row grouping, splitting into multiple tables, summary statistics), not just cosmetic polish; the vault file is what Ryan and Tufte actually edit, so any rendered visual for it is authored local first (an Obsidian `![[filename.png]]` embed saved alongside the note, not a `raw.githubusercontent.com` URL). **Then publish a dated GitHub snapshot** (added 2026-08-19, per Rick's instruction — every update gets one, not just daily-report runs): `Nexus Agents/Agent Tufte/convert_for_github.py` converts local embeds to raw URLs, then `nexus-git-publish.sh` pushes the converted copy plus that update's diagram PNGs to `reports/YYYY-MM-DD-adversary-tracking-report.md` and `reports/images/YYYY-MM-DD-adversary-tracking-report/` — exact command form in the Adversary Tracking Report's own Maintenance section. Flags library candidates, passes to Turing.
8. **Turing** — *Should any of this become a skill?* Queries whether the work performed this round — a research technique, a repeatable analysis, a new tool integration — is worth turning into a reusable skill. If he builds one, he documents it in a **"New Skills" section** placed under the Sources section. Most runs won't produce one — say so plainly rather than manufacturing a skill that doesn't exist. Passes the draft to Bradlee.
9. **Bradlee** — *So, what's the answer?* Reads everything the other agents produced — Sherlock's facts, Ryan's adversary/kill-chain characterization, Euclid's first-principles answer, Popper's objections, Seldon's forecast, Tufte's visualizations, Turing's skill assessment — and writes a synthesis of roughly 500 words that actually answers the question Rick asked. **Writes bottom-line-up-front and free of any reference to the other agents or the internal process (standing convention, 2026-09-04):** the opening one to two sentences state the actual answer, verdict, or number in plain terms — a reader who stops there already has the answer — and the synthesis never names an agent or narrates the process ("Sherlock found," "Popper's objection," "the report is revised to state"); it presents the finding and reasoning directly, in prose fit to run as-is as the lede and body of a Washington Post or New York Times front-page story: plain declarative sentences, concrete facts and numbers, no hedging filler, no meta-commentary on how the answer was produced. Where a First Principles Newsletter Tracker essay bears on the answer, weighs it the same way as any other source — referencing Rick's own prior published position directly ("your own prior position holds," "this cuts against what you argued in...") rather than the Nexus process that surfaced it, consistent with the no-internal-attribution rule. This governs the synthesis section only — Bradlee still privately reads and weighs every other stage's work to run his gatekeeping check below, and every other section of the report keeps naming its own agent as before. **Places it at the very top of the report, immediately after the Question line, with the "Clarifying Questions" section from step 0 directly beneath it** — even though he's the second-to-last agent to touch the draft, readers get the answer first, the scope it was answering second, and the reasoning that produced it follows below. Unlike every other stage, he carries real editorial authority, not just a pass-forward hand-off: before letting the draft proceed, he checks (a) whether Seldon actually resolved each of Popper's objections rather than merely acknowledging them, and (b) whether the draft as a whole answers the question Rick asked. **If either check fails, he sends the draft back to the specific agent responsible** — Seldon if an objection was left dangling, Euclid, Ryan, or Sherlock if the answer itself doesn't hold up — with a note on what's missing, and re-reviews once it returns. This is a distinct, narrower mechanism than the informal loop-back described below (which is any stage asking an earlier one for more detail) — Bradlee's is a formal gate that can hold up publication. Passes the draft to Alexandria.
10. **Alexandria (closing)** — Evaluates every artifact-library recommendation flagged in steps 2–7, adds her own judgment, and presents that recommendation to Rick — he decides, she doesn't merge anything herself (per `Nexus Artifact Repository.md`, unchanged). **Give the recommendation its own structured "Library Recommendations" section, placed under the Sources section (and under "New Skills" if Turing added one) — don't just leave it as prose inside Alexandria's narrative.** Mirror the New Skills pattern: name the candidate, its category (`essay`/`book-review`/`fact-sheet`/etc.), why it's reusable beyond this report, and its status (recommended, awaiting Rick's decision — not yet submitted). A recommendation that only exists as a sentence in the middle of the report is easy to miss; a future reader — including Rick — should be able to find "what did Alexandria recommend archiving" without rereading the whole narrative. If nothing was flagged as worth keeping, state that plainly in this section too, rather than omitting the section entirely. Then **she** — not Turing — publishes: write the report to a local scratch file first, then publish it with `.claude/scripts/nexus-git-publish.sh "https://github.com/raceBannon99/The-Nexus.git" <clone-parent-dir> main "YYYY-MM-DD: <Question/Topic Title>" "<local-file>:reports/YYYY-MM-DD-topic-slug.md"` (add further `<local>:<dest>` pairs for any Tufte images, e.g. `<local-png>:reports/images/YYYY-MM-DD-topic-slug/<name>.png`) — already allowlisted as a single fixed command; it clones fresh into a `mktemp`-generated directory, copies the file(s) in, commits, and pushes to `main` in one shot. **Do not hand-write the clone/commit/push sequence** — every time this has been done by hand instead of through the script, it's ended up wrapped in a `CLONE_DIR="..."` variable that breaks the allowlist match and prompts for permission on every step.

**Format selection** happens alongside this, not as a separate step: there's no fixed template — pick whatever the question actually needs (decision memo, comparison matrix, scenario brief, etc.), informed by Alexandria's and Sherlock's early read and finalized once Tufte's and Turing's passes are done.

**The Sources section is still mandatory on every report** — it just isn't compiled from scratch at the end anymore, since Alexandria starts it in step 1 and every stage through Tufte adds to it. By the time it reaches Alexandria's closing pass, deduplicate, group logically (primary/official, forensics/technical, news coverage, cross-incident analogy, internal precedent, etc.), and make sure every entry has publisher/title, URL, and a one-line note on what claim it supports. Never fabricate a URL — label unverifiable claims as uncited general coverage instead.

If a stage's own findings aren't enough to answer its guiding question, it's fine to loop back and ask an **earlier** stage for more detail before finalizing (e.g. Euclid asking Sherlock to dig deeper on a fact) — ordinary good practice, not a separate formal mechanism. Bradlee's gatekeeping check (step 8) is different: it's a formal, named mechanism that can hold up publication, not an ad hoc request for more detail.

## Update passes

For a revision to an **already-published** report (adding sources, fixing a figure, incorporating a new source, etc.) — do not re-run the full ten-stage sequence. Instead:

1. **Triage** the request against the agents' guiding questions:

   | Nature of the change | Agents to run |
   |---|---|
   | Structural/presentational only, no new claims (e.g. adding a source list for claims already in the report) | Alexandria only |
   | A new or corrected fact | + Sherlock |
   | Touches adversary/campaign characterization, attribution tagging, or kill-chain framing | + Ryan |
   | Touches a conclusion Popper previously challenged | + Popper (must re-review — a prior resolution can't be silently invalidated) |
   | Changes interpretation/first-principles framing | + Euclid |
   | Changes a forward-looking claim | + Seldon |
   | Needs a new or changed visualization | + Tufte |
   | Involved a new repeatable procedure worth checking for a skill | + Turing |
   | Newly cites, or changes the bearing on, a First Principles Newsletter Tracker thesis | + Sherlock |

   When unsure whether something counts as "new claims," default to including Sherlock. A Ryan-only re-characterization that doesn't change Euclid's interpretation doesn't require Euclid to re-run; if it does, treat it as touching Euclid's row too. Bradlee doesn't get his own triage row — whenever Euclid, Popper, or Seldon are re-run, Bradlee also re-runs, to re-verify his top-of-report summary still answers the question and that Seldon actually resolved whatever Popper raised. A pure Sherlock-only, Ryan-only (non-cascading), or Tufte-only Update Pass doesn't require Bradlee.
2. Run only the implicated agents, in the same relative order as a full engagement. If Popper's re-review raises new pushback, resolve it explicitly before finishing.
3. **Alexandria** always runs last: fetch the current published file, edit it in place (no new file) at a local scratch path, then publish with `.claude/scripts/nexus-git-publish.sh "https://github.com/raceBannon99/The-Nexus.git" <clone-parent-dir> main "YYYY-MM-DD: <short description of the update> — <Question/Topic Title>" "<local-edited-file>:reports/YYYY-MM-DD-topic-slug.md"` (same script and same rule as a full engagement — never hand-write the clone/commit/push sequence, it breaks the permission allowlist every time).

Full detail in `Nexus Workflow.md` under "Update Passes" — re-read it if this section seems out of sync.
