# Nexus Daily Intelligence Report

Produces the "First Principles Daily Intelligence Report" by running today's pull across all active sources through a **reduced chain: Sherlock → Ryan → Tufte → Seldon → Alexandria → Turing.** This is a deliberate, standing exception to the Nexus's normal nine-agent process (see the `nexus` skill and `Nexus Workflow.md`) — per Rick's standing instruction (2026-07-16), the daily report does not need Euclid's first-principles threads or Popper's stress-testing/pushback. Ryan joined the reduced chain on 2026-08-17, specifically to maintain the Adversary Tracking Report — the one piece of standing state the daily report needs to update every cycle. Tufte joined the same day, immediately after Ryan: once that table grew past a couple dozen rows it became hard to read, and Rick decided the two should maintain it jointly going forward — **Ryan determines what needs to be added or changed, Tufte determines how it's presented** (column structure, grouping, splitting into multiple tables — real structural authority, not just formatting). **Seldon joined on 2026-09-11**, but on a much narrower brief than Ryan/Tufte — he does not do general forecasting on the day's other stories; his only job is maintaining a second standing artifact, the Singularity Forecast Report (a P5/P50/P95 range for when the world might lose irreversible control of frontier AI), updated whenever Sherlock CIR-matches evidence to the "AI Singularity Timeline" category. **A second, parallel standing artifact was added 2026-09-18**: the AGI Forecast Report (a separate P5/P50/P95 range for when a machine first matches broad human performance — a capability question, not a control one), updated whenever Sherlock CIR-matches evidence to the "AGI Arrival Timeline" category. **A third followed the same day**: the Superintelligence Forecast Report (when a machine might exceed, not just match, human intelligence) — methodologically different from its two siblings, since no external forecaster basket targets this question; its range is structural inference off the AGI file's own range plus a reasoned transition-gap model, and it carries a standing confidence caveat every time it's cited. Seldon runs the identical narrow procedure against all three files in sequence, kept strictly separate. Just facts, adversary-campaign tracking and formatting, three narrowly-scoped forecasts, curation against prior reports, and a clean published digest. If Rick ever wants the full nine-agent treatment on a daily pull, he'll ask for it explicitly (e.g. via the `nexus` skill on a specific story from the day) — don't default back to the full chain without being told to.

## Known gotchas

Sources.md's "Known Tooling Limitations" section is authoritative if this list drifts out of date — check there first:

- **Standing rule: any failed WebFetch gets a Chrome MCP retry before the link is marked unavailable.** `navigate` + `get_page_text` (the same pattern used for The Record) is the default fallback for every **website** source, not just ones with a documented history of blocking WebFetch. Only note a link as unreachable if Chrome MCP fails too. **Doesn't apply to Gmail Newsletters** — that source uses a separate, dedicated Gmail Connector (`mcp__claude_ai_Gmail__*`), never WebFetch or Chrome MCP, so it's unaffected by any Chrome extension outage. If Chrome MCP is down, don't treat Gmail as at-risk too — check it independently.
- **Chrome extension outage, ongoing as of 2026-07-31** — `list_connected_browsers` empty, `tabs_context_mcp` won't pair, even after confirming the right account, a reinstall, and a restart. Bug filed: [anthropics/claude-code#82879](https://github.com/anthropics/claude-code/issues/82879). While open, skip retrying Chrome MCP repeatedly and just log the affected website sources (The Record, Canon Project, Wired's own RSS/site path, arstechnica.com-style blocked domains) as No Contribution (outage).
- Gmail `get_thread` on HTML-heavy senders can exceed token limits — use `search_threads` snippets instead.
- Cyberwire has no confirmed stable per-story permalink — link to the Daily Briefing directory page and say so explicitly rather than guessing a URL.
- arstechnica.com blocks both WebFetch and WebSearch entirely (a site-side block, not a permissions gap) — confirmed 2026-07-17 that the Chrome MCP fallback above works cleanly here (category page and individual article both retrieved in full, no CAPTCHA/bot-challenge), when Chrome MCP itself is working.
- FFX Now's extraction has missed a story on a first pass before — a second pass is cheap insurance if the item count looks low relative to a typical day.
